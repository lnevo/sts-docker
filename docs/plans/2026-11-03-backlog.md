# STS backlog and execution plan

Written 2026-11-03. This lists what is outstanding after the UI pass and API v1,
in the order it will be done. Items marked **(owner)** need a decision or a
device from the owner; everything else runs unattended through the gate in
[HANDOFF.md](HANDOFF.md).

## In flight

1. API phase 2: browser sign-in, command-role policy, admin page under Database
   Maintenance, editor endpoints, per-step role checks with warnings, lock on
   the legacy editor endpoints, remaining endpoint gaps.
2. Move the session editor onto v1. It opens read-only until you sign in, shows
   role warnings before Run, and polls the task log during a run.

## Wave 1: legacy hardening (parallel, separate worktrees)

- **W1a, security fixes in the CRUD family and the AJAX endpoints.**
  - Prepared statements: `db_list_*` (the worst is `db_list_jobs.php:32`, which
    runs `create table` on a raw POST value), `db_edit_*` (which delete on a
    GET), `update_car_ajax.php`, `add_remove.php`, `auto_assign.php` and
    `build_switchlists.php`.
  - `remove_img.php`: restrict the filename with `basename` and a whitelist.
  - `get_table_guts.php:14` calls `$mysql_error`; use `mysqli_error`.
  - `db_edit.php`: drop the branch for the missing waybills include.
  - Escape output on the pages touched.
- **W1b, shared helpers and inline CSS.**
  - One escape helper (`sts_h`), with `ops_h` and `sm_h` as aliases.
  - Move the large inline `<style>` blocks on the step pages into
    `operations_ui.css`: `fill_orders.php` (268 lines), `organize_cars.php`,
    `pick_up.php`, `set_out.php`, `generate.php`, `load_unload.php`,
    `reposition.php` and `operations.php`. No visual change.

## Wave 2: after phase 2 and the editor land

- **W2a, API integration tests and CI.**
  - A stdlib Python suite in `tests/api/` that runs against a sandbox: auth and
    roles, every route's happy path and errors, tasks, sign-in, policy.
  - A GitHub workflow that builds the sandbox, restores a small fixture and runs
    the suite.
- **W2b, agent plugin and skill.** Tools for sign-in-free policy reads, the
  editor endpoints and output clearing; updated skill and tests.
- **W2c, helpers.** Move the last docker paths onto the API: location aliases,
  clearing switch-list output, and `--ck1-test` through the warm-start `config`
  object.
- **W2d, review.** An independent pass over phase 2 and the editor migration,
  then fixes.

## Wave 3: legacy pages

- **W3a, report forms and printables.** Fold each `display_*` / `printable_*`
  pair into the single-file `?generate_report=1` pattern (fleet, car QR, station
  QR, waybill, then switch list). Print output is compared before and after with
  browser print-to-PDF.
- **W3b, data editor bodies.** In `db_list_*` / `db_edit_*`, replace the
  heading-injection JS with variables the shell renders, and give the tables the
  shared classes.
- **W3c, one navbar.** `ops_render_navbar` and `session_nav_bar_html` render
  through the `page_chrome.php` partial. The hand-written navbars go:
  `list_cars`, `wheel_report`, `session-sitemap`, `display_station_report`,
  `so.php`, `operational_steps_api.php`.
- **W3d, error visibility.** `open_db.php` logs failed queries to stderr instead
  of suppressing them, without changing page output.

## Wave 4: documentation
